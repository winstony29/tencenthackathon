# DCTA: voice banking agent

Tencent Cloud Hackathon 2026 · DBS case study (DCTA), Scenario 1: voice payments.
Speak a banking command; the AI drafts it, a second model checks it, and money moves only after you sign it on your phone.

Background: `docs/BRIEF.md`. Coding assistants: read `AGENTS.md` first.

## Run locally

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # then fill in your keys
uvicorn app.main:app --reload
```

Open http://localhost:8000/docs for the API. Run the frontend below for the app.

## Test

```bash
pytest
ruff check . && ruff format --check .
```

## Front end

See D-004 in `docs/DECISIONS.md`.

The first UI slice supports typed requests, browser recording against the ASR stub,
clarification, draft cards, related data, and validation. Signing is not connected yet.
Example buttons load labelled UI fixtures; they never execute a transaction.

On Windows, keep the backend running in one terminal:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

In a second terminal, from the repo root:

```powershell
cd web
npm.cmd install
npm.cmd run dev
```

Open http://127.0.0.1:3000. The development server proxies `/api/` to FastAPI;
no CORS change is needed. Bun can run the same package scripts.

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run test:browser
```

Browser checks require both servers and Chrome (override `CHROME_PATH` for another
Chromium executable). Screenshots are written to ignored `graphify-out/`.
The production build writes `web/out/`; FastAPI mounting remains an integration task.
The backend currently serves only API routes; its `/` page is not mounted yet.


The adaptive workspace has three explicit demo scenarios: Send money (focus),
Two tasks (sequence), and Can I afford it? (canvas). Forms are editable locally;
layout controls preserve edits. Approve each action before reviewing the plan.
API edits require a fresh backend draft; the client will not submit stale values.
Presentation selection is currently a labelled demo/fallback, not live JEV.
See D-017 for the proposed presentation handoff. Affordability projections remain
separate by account and currency and exclude fees, taxes and currency conversion.
Scenario screenshots are generated by browser tests under `graphify-out/scenario-*`.

The separate conversational experiment is at http://127.0.0.1:3000/v2/;
the original workspace remains at `/`. Start with “Send money to John”, choose
the listed recipient and enter an amount. Return to conversation to ask about
affordability or say “Actually, make it $300 and use my savings account”.
Unrelated form edits survive both changes. Bill-and-Apple-share requests use
the same state machine and presentation engine. Review and confirmation happen
after editing, and produce a clearly labelled local demo result only.

V2 includes an explicit mock Winston output selector. Click “Compose with live JEV”
to call EdgeOne's native System One endpoint through the local FastAPI server.
Typing alone and direct form edits do not trigger JEV. Repeating composition for
the same output preserves edits. Open “How this workspace was composed” to inspect
eligible choices, the checked manifest and actual System One answers/confidence.
The resolved tasks and banking records remain mock; no Claude processing is added.
Its strict presentation
selection covers interaction, focus, support components, tools, density, strategy,
layout and primary action. A future server-side transport can supply approved
option IDs; malformed or unavailable responses fall back safely. No banking
contract or execution API is changed. See D-018 and D-019 for integration limits.
Browser tests save `graphify-out/v2-*` desktop and mobile screenshots.

Set `MAKERS_MODELS_KEY` in the server environment or `.env` (the dotenv loader
also finds the parent workspace `.env`). Restart FastAPI after changing the key.
The experimental `POST /api/presentation-demo?fixture=transfer|partial|multi|decision`
accepts only those four fixture IDs. The key is read by `app/config.py` and is never
sent to the browser. A deployed static frontend still needs FastAPI to serve this
route under the same origin; do not put the key in a `NEXT_PUBLIC_` variable.
