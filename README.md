# DCTA: voice banking agent

Tencent Cloud Hackathon 2026 · DBS case study (DCTA), Scenario 1: voice payments.
Speak a banking command; the AI drafts it, a second model checks it, and money moves only after you sign it on your phone.

Background: `docs/BRIEF.md`. Coding assistants: read `AGENTS.md` first.

## Run locally

One server runs the whole app: FastAPI serves the API and the built front end.

```bash
# once
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # then fill in your keys (MAKERS_MODELS_KEY for live Jev)
cd web && npm install && cd ..

# after every pull that changes web/
cd web && npm run build && cd ..

# start
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000/v5/ for the app (`/` and `/v4/` are earlier versions) and
http://127.0.0.1:8000/docs for the API.

| `MAKERS_MODELS_KEY` in `.env` | What runs |
|---|---|
| set | Live Jev: the real intent engine reads requests and composes the screen |
| empty | Contract stubs (CONTRACTS §7): every request gets the same example replies |

Set `AUDIT_EVIDENCE_KEY` and `AUDIT_ADMIN_TOKEN` too (see "Audit evidence" below):
without them every audited endpoint answers 503.

Accounts, payees and prices come from `data/bank.json`. Validation and the bank challenge
are real; execute is not built yet and fails closed, so no money moves. Voice uses the ASR
stub; type requests instead. The first "Transfer now" pins that browser's device key in
`var/devices.json`; delete the file to use another browser.

To work on the front end with live reload, run `npm run dev` in `web/` alongside the
server and open http://127.0.0.1:3000/v5/ instead.

## Front end

See D-004 in `docs/DECISIONS.md`.

`/v5/` is the main interface: it sends typed requests (and its demo shortcuts) to the
real intent engine, shows its clarifying questions, builds the cards from real bank
data, and signs with a device key. Validation, challenge and execute are still stubs,
so signing stops at the stub challenge. `/` supports typed requests, browser recording
against the ASR stub, clarification, draft cards, related data and validation.

On Windows, keep the backend running in one terminal:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

In a second terminal, from the repo root:

```powershell
cd web
npm.cmd install
npm.cmd run dev
```

Open http://127.0.0.1:3000. The development server proxies `/api/` to FastAPI;
no CORS change is needed. Bun can run the same package scripts.

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run test:browser
```

Browser checks require both servers and Chrome (override `CHROME_PATH` for another
Chromium executable). Start the backend without a Jev key (`MAKERS_MODELS_KEY=` set
empty) so `/api/understand` answers with the contract stubs these checks expect.
Screenshots are written to ignored `graphify-out/`.

`npm run build` writes `web/out/`, which FastAPI serves: after a build, the backend
alone runs the whole app at http://127.0.0.1:8000/v5/.


The adaptive workspace has three explicit demo scenarios: Send money (focus),
Two tasks (sequence), and Can I afford it? (canvas). Forms are editable locally;
layout controls preserve edits. Approve each action before reviewing the plan.
API edits require a fresh backend draft; the client will not submit stale values.
Presentation selection is currently a labelled demo/fallback, not live JEV.
See D-017 for the proposed presentation handoff. Affordability projections remain
separate by account and currency and exclude fees, taxes and currency conversion.
Scenario screenshots are generated by browser tests under `graphify-out/scenario-*`.

The separate presentation experiment is at http://127.0.0.1:3000/v2/;
the original workspace remains at `/`. Winston owns conversation, task routing,
objectives and ambiguity resolution. V2 receives complete outputs only; it has
no local command parser or missing-information form.

Choose a complete mock Winston output and click "Compose with live JEV".
For one transfer, try ready-to-edit, affordability, recipient checking and
updated-to-$300 outputs in sequence. Compatible local edits survive objective
changes. An upstream change to a field takes precedence over that field's local
edit. New draft IDs clear edits. All handoffs clear review approvals.

JEV chooses a coherent approved bundle, layout and density; multiple tasks add
visual priority. No model selects task values or interprets user prompts.
Affordability bundles always include projections; simulation additionally
includes task-local sliders. Weak presentation preferences retain eligible
current choices when the objective is unchanged (experimental 0.15 margin).
Direct field edits do not call JEV. Cancelled responses are ignored; malformed
or unavailable responses use the labelled fallback. Open "How this workspace
was composed" for choices, stability reason and actual model answers.

`POST /api/presentation-demo` now accepts a strict structural JSON body with
`action_types`, `complete: true`, `missing: []`, `objective`, `recipient_status`,
`available_context` and optional `current_ui`. It rejects incomplete outputs,
unknown fields and inconsistent context. This isolated experimental format is
not the shared Winston banking contract. The real handoff is still pending;
the selector and balances remain explicitly mock. See D-021.

Review and confirmation produce a local demo result only. Backend validation,
signing and execution remain separate. No Claude processing is added.
Browser tests save `graphify-out/v2-*` desktop and mobile screenshots.

Set `MAKERS_MODELS_KEY` in the server environment or `.env` (the dotenv loader
also finds the parent workspace `.env`). Restart FastAPI after changing the key.
The key is read by `app/config.py` and is never sent to the browser. A deployed
static frontend needs FastAPI under the same origin; do not put the key in a
`NEXT_PUBLIC_` variable. The presentation route remains a local demo, not a
public authenticated production endpoint.


### Audit evidence

Install the updated requirements. Set persistent `AUDIT_EVIDENCE_KEY` (a Fernet key) and
`AUDIT_ADMIN_TOKEN` (an independent random token) in `.env`. Generate them once locally;
never commit them or regenerate on every startup. For a fresh setup:

```python
from cryptography.fernet import Fernet
from dotenv import find_dotenv, set_key
import secrets
path = find_dotenv(usecwd=True)
# Only run for a NEW installation; replacing the key loses access to previous evidence.
set_key(path, "AUDIT_EVIDENCE_KEY", Fernet.generate_key().decode())
set_key(path, "AUDIT_ADMIN_TOKEN", secrets.token_urlsafe(32))
```

Inspect the latest protected timeline from the repository directory (Windows or macOS):

```python
import httpx, json
from app import config
response = httpx.get("http://127.0.0.1:8001/api/audit/timeline",
    params={"limit": 100, "include_evidence": "true"},
    headers={"Authorization": "Bearer " + config.AUDIT_ADMIN_TOKEN})
response.raise_for_status()
print(json.dumps(response.json(), indent=2))
```

Add `session_id` to filter a conversation. The output contains sensitive banking context;
do not paste it publicly. Records survive server/session restarts in ignored
`var/evidence.sqlite3`. Retention, trust boundaries and limitations are in CONTRACTS v0.8.

### Deploy publicly

The server is a single-process demo. Before giving judges a public URL:

1. **HTTPS only.** Browsers disable the WebCrypto signing V5 needs on plain `http://`. Put
   it behind EdgeOne or a load balancer with a certificate, and add HSTS there.
2. **Secrets** in the host's secret store, never in the image: `MAKERS_MODELS_KEY`,
   `AUDIT_EVIDENCE_KEY`, `AUDIT_ADMIN_TOKEN`, `VALIDATION_RECEIPT_KEY`, `MASK_KEY`.
3. **Validator:** `VALIDATOR_PROVIDER=compatible-api` with its own `LLM_BASE_URL`,
   `LLM_API_KEY` and `VALIDATOR_MODEL`. Never sign a personal Codex account in on a server:
   anonymous visitors would spend its quota.
4. **Leave `API_DOCS` unset** (off): `API_DOCS=1` shows `/docs` and `/openapi.json`.
5. **Real client IPs for rate limits:** run `uvicorn app.main:app --proxy-headers
   --forwarded-allow-ips=<proxy address>` with the proxy's exact addresses or ranges,
   **never `*`**: with `*` any client picks its own IP and escapes every limit; without the
   flag every visitor shares one limit.
6. **Build with `npm ci`** so the front end uses the locked dependency versions.
7. **Device keys:** the first browser to sign owns `u_demo` until `var/devices.json` is
   deleted. Pre-register the demo device, or keep the server private until Jayanth adds an
   enrollment code.

Limits (`app/config.py`): 256 KB JSON bodies, 2 MB audio; per IP per minute 40 model calls,
120 previews, 120 validations, 60 writes and 120 reads; 600 model calls and 600 previews a
minute in total. They live in memory, as do sessions, so run one worker. Every key and token
must be at least 32 random characters and differ from the others, or the server won't start.
To rotate `AUDIT_EVIDENCE_KEY`, set it to `new,old` and keep the old key while its rows remain.
